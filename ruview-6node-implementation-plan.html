01WiFi CSI 感知原理

1.1 信道频率响应：房间电磁场的"低分辨率雷达快照"

WiFi 路由器发射的 OFDM 信号把频带切成大量正交子载波。接收端对每个子载波 k 估计一次信道频率响应：

H(fk) = |H(fk)| · ejφk　　（幅度 × 相位，即一帧 CSI）

幅度 |H| 反映该子载波上多径叠加后的能量强弱；相位 φ 反映多径传播的时延结构。ESP32-S3 每帧输出 56 个子载波的 I/Q 对（HT20 带宽），采集速率约 20 Hz——相当于以 20 Hz 对房间的电磁散射场做一次 56 维快照。

1.2 人体如何扰动多径

  • 含水组织是高散射体：人体改变传播路径上的介电环境，直接改写幅度与相位；人移动时等效产生类多普勒的相位漂移，特定子载波幅度随之起伏。
  • 菲涅尔区机制：收发器连线周围的菲涅尔区被穿越时，反射径与直射径干涉产生周期性幅度变化——这是"人走过某条链路"的物理基础，也是仓库 fresnel.rs 呼吸几何模型的来源。
  • 生理频带（ADR-021 依据）：胸腔起伏 1–5 mm，落在 0.1–0.5 Hz；心跳体表位移 0.1–0.5 mm，落在 0.8–2.0 Hz。这两个极窄的频带是呼吸/心率监测从相位里提取的物理前提。

02信号处理流水线

2.1 相位净化：为什么原始相位不能直接用

消费级 WiFi 芯片输出的相位被载波频偏（CFO）与采样频偏（SFO）污染——收发两端晶振不一致时，相位含一条随时间线性漂移的公共分量。两条工程化解法：

  • SpotFi 式共轭相乘（CSI Ratio）：用相邻天线/相邻帧的 CSI 共轭相除，公共频偏项相消，留下相对相位（csi_ratio.rs）；
  • 子载波一阶差分：训练模型内部同样用相邻子载波差分消除共模漂移（model.rs 的 phase_sanitize，无参数、可微）。

phase_sanitizer.rs 再做解卷绕、离群剔除与平滑，是 ADR-014 六项学术 SOTA 引入之一。

2.2 空房基线与运动检测（Welford）

家具、墙体构成强静态多径，直接看绝对幅度没有意义。ADR-135 的做法：空房 30 秒（600 帧 @20 Hz）采集，用 Welford 在线算法统计每个子载波的幅度均值/方差与圆形相位均值/方差；之后运动判据改为基线相对 z-score：rms_amplitude_z > 3.0 才算"有东西在动"。内置 staleness 检测，家具移动后触发重标定，基线约 24 h 过期。

2.3 多节点融合：为什么坚持特征级、不做原始相位对齐

核心工程决策（ADR-012）

ESP32 晶振精度 20–50 ppm：漂移率为 20–50 µs/秒，100 秒即累积 2–5 ms 偏移——而相位对时钟误差的敏感度在 µs 量级，跨节点做原始相位对齐在物理上不可行，任何声称"多节点相位联合定位"的方案在消费级晶振下都不成立。因此仓库明确：motion 各节点取 max、呼吸取 SNR 最高节点、位置用幅度比——只做特征级融合。

MultistaticFuser 的现行参数：guard_interval_us=60000（硬）/ soft_guard_us=20000（软），S3 独立晶振场景官方注释建议调至 WDP_GUARD_INTERVAL_US=200000。历史教训写在代码注释里：旧 5 ms guard 曾拒绝所有真实 TDM 帧，导致融合从未真正运行（#1031）。

风险 现状的"多节点"实质是每个节点↔路由器的被动链路 × 6 个空间视角的特征级融合——固件 TDMA 发射调度（ADR-029 规划的 sensing_schedule.c）与 NDP 主动探测注入均为桩代码，30 条受控 bistatic 链路是规划不是现实。6 节点的现实收益是 6 个视角的幅度/特征融合。

03人数感知：两条路线的深度对比（全文主线）

3.1 未训练路线：mincut 图割 + 加权启发式

算法细节（sensing-server 内置实现，全部硬编码）

  1. 相关性建图：20 帧滑窗（~1 s）内对 ≤56 个子载波算幅度时序的 Pearson 相关；|r| > 0.1 建边（独立脚本 mincut-person-counter.js 为 0.3），边权 = |r|×10。物理直觉：被同一移动人体扰动的子载波幅度时间上相关，两个独立移动的人形成两组相关簇。
  2. 最小割：源/汇接最高/最低方差子载波，跑精确 max-flow 得 cut_ratio = 割权/总边权。判据：cut_ratio > 0.4 → 1 人；> 0.15 → 2 人；else → 3+ 人。总方差低于噪声底（1.0）→ 0 人。
  3. 锚点映射：割计数 → 分数 {0→0.20, 1→0.40, 2→0.74, 3→0.96}（#803 修复前的旧锚点把两人永远钉死在 1），再与加权启发式 person_score = 0.40·variance + 0.20·change_points + 0.25·motion_band + 0.15·spectral（rolling-P95 自适应归一化）融合。
  4. 时域整形：EMA（score = 0.92·score + 0.08·raw）+ 滞回离散化：上行 0.70→2 人、0.85→3 人，下行 0.55（2→1）、0.78（3→2），非对称间隙 0.25/0.14 防抖动（#237/#249/#280/#292 四轮修复）。聚合层再取 max(活动计数, 各节点 max)——只能抬不能压。

对 mincut 的定位结论

mincut 路线只适合两件事：① 部署后零训练验证"链路通了、有人在动就有响应"（冷启动验收）；② 训练式模型故障时的 fallback。它有 2 秒滑窗延迟、看不见静止人员、跨房间会泄漏——不能作为交付方案。这就是本文把人数感知重构为训练优先路线的原因。

为什么训练路线能解决静止人员问题

mincut 的盲区是原理性的：信号 = 运动。CountNet 学的是"CSI 幅度模式 → 人数"的映射，只要训练集里有静止段（坐/站 session，见 §8），"有人在但不动"就是一种被监督信号覆盖的输入模式——模型可以从静态人体的多径遮挡特征（幅度水平的持续偏移，而非时序变化）中学到"有人"。这正是把人数感知切换到训练路线的根本理由。

3.3 物理先验辅助：field_model 的 SVD 占用估计

已实现并已接线的第三条腿（field_model.rs::estimate_occupancy()）：对 56×56 幅度协方差做特征分解，用 Marcenko-Pastur 阈值 λth = σ²·(1 + √(n/count))² 区分"信号特征值"与纯噪声特征值，占用数 = 显著特征值数 − 基线特征值数（cap 10，单链路再钳到 3）。风险 使用门槛：需 eigenvalue feature（BLAS）、必须先空房校准建立基线特征值数、每次调用 O(n³)；仓库无精度基准（只有一个"空房=0"的不变量单测）。定位：交叉校验与物理先验，不是可交付计数器。

04姿态识别原理

4.1 端到端模型结构（wifi-densepose-train，复现 CMU arXiv:2301.00250）

amplitude [B, T·tx·rx, 56] ─┐ ├─► ModalityTranslator ─► [B, 3, 48, 48] 伪图像 phase [B, T·tx·rx, 56] ─┘ │ （相位先做子载波一阶差分净化，无参数可微） ▼ ResNet18 backbone ─► [B, 256, 12, 12] │ ┌───────────────┴───────────────┐ ▼ ▼ KeypointHead DensePoseHead [B, 17, 56, 56] 热图 [B, 25, 56, 56] 部件 + [B, 48, 56, 56] UV

要点：ModalityTranslator 把一维 CSI 翻译成二维伪图像（幅度/相位各走 flat_csi→512→256 双 FC 分支，拼接后 reshape 为 3×48×48，再过两层 Conv + tanh），之后复用成熟的 2D 视觉 backbone——这是"WiFi 看见人"的核心思想。天线对维度另有 mincut 门控注意力做自动天线选择。损失权重 λkp=0.3 / λdp=0.6 / λtransfer=0.1（后者向 RGB 教师特征做跨模态蒸馏，是 CMU 论文的关键贡献）。

4.2 边缘部署形态：PoseNet（cog-pose-estimation）

家庭部署实际用的是小型 Conv1d TCN：Conv1d(56→64, d=1) → (64→128, d=2) → (128→128, d=4) → 时间均值池化 → Linear(128→256) → Linear(256→34) → sigmoid → [17,2] 关键点。输入 [1, 56, 20]，125K 参数 / 507 KB；Pi 5 冷启动 8.4 ms、稳态 ~305 µs 事实。与 CountNet 共享同一输入格式（56×20 窗口），这是两条训练线能共用数据管线的原因。

4.3 LoRA 房间适配：为什么少量样本就有效

跨环境部署的根本困难：CSI 的房间指纹性极强，换一个房间，同样的姿势对应完全不同的输入分布（MM-Fi 实测跨环境 zero-shot 从 in-domain 82.69% 崩到 ~10% 事实）。LoRA 的思路：冻结基础模型，只学一个低秩增量 ΔW = B·A（rank-8），作用在输入投影与姿态头两层——它不重学"人体长什么样"（这是基础模型已会的），只学"这个房间如何把 CSI 映射到同一个姿势空间"，即房间特有的系统性偏移。低秩约束天然防过拟合，所以 100–200 样本即可拟合 11,200 个参数（~11 KB int8）。

7.2 修复二：人工时间段标注（对静止场景最可靠，必做）

MediaPipe 漏检最严重的恰恰是静止坐着/躺着的人（ADR-103 记录 P7 session 检测率仅 47%——一半的帧在人明确在场时仍标 0 人）。而"静止人员"正是训练路线相对 mincut 的核心价值，标签必须可靠。方案：

  1. 采集时人工记录日志：14:02:10–14:05:00: 2 人、14:05:00–14:08:30: 1 人（坐沙发）……
  2. 写一个小脚本（~30 行 Python）把时间段标签 patch 进 paired.jsonl 的 n_persons_mode 字段——落在时间段内的所有窗口直接覆盖标签。
  3. 人工标注天然产出"静止人员"标签——这是 mincut 结构上永远学不到、而训练路线唯一的来源。

7.3 修复三：conf ≥ 0.7 过滤

ADR-103 §Risks 建议对 MediaPipe 输出按置信度 ≥0.7 过滤（align 脚本已有 --min-confidence 0.5 门槛，训练管线前建议提高或在 patch 脚本里过滤低置信窗口）。目标数据量口径（ADR-187）："≥30K paired samples at conf ≥ 0.7"。

9.2 新发现的 shape 不兼容坑（必须在训练前修复）

坑：新数据会被训练脚本静默跳过，0 样本

align-ground-truth.js 在 #1007 Bug 4 修复后改为 frame-major 输出：csi_shape = [nFrames, nSc] = [20, 56]；而 train-count.py L76-78 仍硬性过滤 csi_shape == [56, 20]（旧的错标顺序）。用当前 align 脚本新生成的 paired 文件，会被 train-count.py 全部静默跳过——训练样本数为 0 且不报错。

修复（二选一，训练前必做）：① 在 train-count.py 读取处对 [20,56] 做转置（或把过滤改为同时接受两种 shape）；② 在 patch/预处理脚本里统一写回 [56,20]。改完后先跑一遍小样本确认样本数非 0。

9.3 窗口参数联动的坑

若想加长窗口（如 40 帧提高静止段信噪比）：align 脚本的 --window-frames/--window-ms 可调，但 train-count.py L76-78 的过滤与 CountNet 输入维度（[B,56,20]，与 Rust 推理端逐位一致）都要同步改——默认 20 帧窗口不要动，否则推理端无法加载。

10.5 与文献的硬件差距（诚实说明）

文献对照（ADR-103 L15-23）：WiCount 89%±1、DeepCount 92%±1 的人数统计精度，均基于 3×3 MIMO 研究网卡（如 Intel 5300）。ESP32-S3 是 1×1 SISO、56 子载波、消费级晶振——"published number is therefore not directly attainable"。家庭部署的合理预期：0/1 占用高可靠，±1 精度靠多房间数据逼近 ADR-103 门槛，绝对人数（尤其 2+）以 k-fold 实测为准、不引用文献数字。仓库没有任何 2+ 人实测数据（标签从未存在），预期值只能靠本次采集后的 k-fold 给出。

12.3 预期（诚实版）

MM-Fi 的证据是在 3 天线 × 114 子载波的硬件上取得的。ESP32-S3 单节点是 1×1×56，信息量更低，仓库没有 ESP32+LoRA 的实测闭环——首次自训的目标应定在"超越 mean-pose 基线、近端关节（髋/肩）可用"，而不是论文级 PCK。当前 ESP32 自有数据的残酷基线：1,077 样本坐姿训练得 PCK@20 = 3.0%，且 2,046 窗口上所有微调跑法均未超过 mean-pose 基线 95.9% 事实——被明确判定为 data-bound（数据受限）而非基建受限，这正是 §8 数据协议（多场景、多会话、多房间）同时服务于姿态线的原因。验收口径一律用 torso-PCK@20 canonical 指标并报 vs mean-pose 基线对比（92.9% PCK 的旧宣称已因"模型输出常量姿态"正式撤回，不可引用）。

12.4 多人姿态为什么短期不做

  • ADR-037 全链路为规划态：P1 SVD 人数估计 → P2 NMF 分解 → P3 多骨架生成 → P4 神经多人模型，四阶段在仓库中均无落地实现证据；性能预算 65 ms/帧（15 FPS）、两人相距 <0.5 m 分离不可靠，全是设计目标。
  • GT 管线限制：即使修复 num_poses，MediaPipe 多人骨架在家庭机位下的配对质量也未经仓库验证；当前 align 脚本产出的是单人关键点格式。
  • 短期正确姿势：人数（训练式 CountNet）+ 单人姿态（LoRA）+ 占用/活动标签，不做多人骨架。
