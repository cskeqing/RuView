01项目概述

RuView（前身/别名 WiFi-DensePose）是一个 WiFi 空间感知平台：利用廉价 ESP32 节点采集 WiFi 信道状态信息（CSI），通过信号处理 + 神经网络实现穿墙存在检测、呼吸/心率监测、跌倒检测、人数统计、17 关键点姿态估计等能力。项目的三大核心理念是：

无摄像头
以 WiFi 电磁场代替摄像头成像，天然保护隐私，可穿墙、可在黑暗中工作
无云端
全部感知在本地完成；数据不出房间，可接入 Home Assistant / Matter
边缘运行
从 ESP32 固件到 Raspberry Pi，WASM 热加载模块让感知算法跑在毫瓦级硬件上

02WiFi 智能空间识别原理

从 OFDM 到 CSI：信道如何成为"雷达"

WiFi 路由器持续发射 OFDM（正交频分复用）信号，接收端可以逐子载波估计信道频率响应（Channel State Information，CSI）：

H(f) = |H(f)| · ejφ(f)　—— 每个子载波的幅值与相位，就是房间电磁场的"快照"

人体（约 60% 是水）是 2.4/5 GHz 电磁波的良好散射体与吸收体。人在房间里移动、呼吸、心跳时，会扰动多径传播：

  • 移动 → 产生类多普勒的相位漂移，反映运动速度与方向；
  • 呼吸：胸腔起伏幅度 1–5 mm，频率落在生理频带 0.1–0.5 Hz；
  • 心跳：心跳引起的体表位移仅 0.1–0.5 mm，频率在 0.8–2.0 Hz（ADR-021 给出的生理学依据）。

ESP32 每帧输出 56 个子载波的 I/Q 复数对，以约 20 Hz 速率上报——相当于对房间电磁场做"低分辨率雷达采样"。这就是为什么 WiFi 可以"穿墙看见"人：它看的不是光，而是人体对多径电磁场的扰动。

图 2-1 · WiFi CSI 感知概念：发射端 → 人体扰动多径 → 接收端逐子载波记录 H(f)（纯 SVG 示意）

ESP32 如何采集 CSI

  • firmware/esp32-csi-node/main/csi_collector.c 注册 ESP-IDF 官方 CSI 回调，构建时用 #error 守卫确保 CONFIG_ESP_WIFI_CSI_ENABLED 打开；
  • 每帧按 ADR-018 二进制帧格式序列化每个子载波的 int8 I/Q 数据，经 UDP 发往聚合器（main/stream_sender.c，带 ENOMEM 指数退避保护）；
  • 支持 通道跳频（1 / 6 / 11）做多频段融合（ADR-029），ESP32-C6 之间用 ESP-NOW 32 字节同步包做跨板时钟对齐；
  • 消费级硬件的原始相位被 CFO/SFO（载波/采样频偏）污染，必须经过净化才能用于感知——这正是信号处理流水线的第一步（见第 4 章）。

重点算法详解（ADR-014 引入的 6 种学术 SOTA）

SpotFi 相位净化（CSI Ratio）

消费级硬件相位含 CFO/SFO 共模污染。csi_ratio.rs 实现 SpotFi 式共轭相乘：相邻子载波互乘消除公共相位漂移；phase_sanitizer.rs 再做解卷绕、离群剔除与平滑（ADR-014 §1）。

Hampel 中值滤波

hampel.rs：滑动窗中值 + MAD 判据剔除幅度尖峰，对硬件突发噪声鲁棒，优于均值滤波且不模糊跳变。

菲涅尔区模型（Fresnel）

fresnel.rs：用菲涅尔区几何解释穿墙感知与呼吸引起的相位周期性——人体穿越菲涅尔区边界时相位翻转，胸腔起伏造成可预测的相位调制。

BVP（Body Velocity Profile）

bvp.rs：来自 Widar 3.0 的"身体速度剖面"特征，把 CSI 时频变化映射为等效运动速度剖面，天然具备跨环境迁移性。

生命体征四阶段提取

wifi-densepose-vitals：① EMA 静态抑制 → ② 0.1–0.5 Hz IIR 带通 + 零交叉测呼吸 → ③ 0.8–2.0 Hz 带通 + 自相关峰 + 子载波间相位相干加权测心率 → ④ Welford Z-score 异常检测（呼吸暂停/心动过速）。固件端 edge_processing.c 用同算法在设备端独立运行。

Mincut 人数分离 + AETHER 嵌入

sensing-server 用 ruvector-mincut 图割做人数分离（ADR-075），配合 Kalman PoseTracker 与 FieldModel 场模型；学习式计数器在 cog-person-count（ADR-103）。AETHER（ADR-024）对比学习产出 128 维 CSI 指纹，支持房间识别/异常检测/HNSW 检索，量化后仅 8 KB。

损失函数（src/losses.rs）

Ltotal = 0.3 · Lkeypoint + 0.6 · Ldensepose + 0.1 · Ltransfer
  • 关键点热图损失：预测与目标高斯热图的逐像素 MSE，按可见性掩码（visibility）归一化；
  • DensePose 损失：部件交叉熵（25 类）+ 前景像素 UV Smooth-L1/Huber；
  • 迁移/蒸馏损失：学生 backbone 特征与 RGB 教师特征的 MSE——跨模态知识迁移，是 CMU 论文的核心思想（训练时用相机教师，部署时无相机）。

优化器与调度（trainer.rs L133–137）：AdamW（weight_decay=1e-4），线性 warmup 5 epochs + multi-step 衰减（30/45 epoch ×0.1），梯度裁剪 L2≤1.0，确定性 shuffle（seed XOR epoch）；每 epoch 验证 PCK@0.2 / OKS，按验证 PCK 保存 best checkpoint（safetensors 格式），CSV 日志记录 epoch, train_loss, val_pck, val_oks, lr, …。

08诚实性与局限性（必读）

RuView 的一个突出特点是自我诚实：README L209–226 设有 "Model weights: what's real, what's not" 专章，基准文档严格执行 ADR-152 证据等级标注。以下是必须知道的负面结果与限定：

已撤回 · Retracted

旧的 "92.9% PCK@20" 宣称已正式撤回——模型输出为常量姿态，torso 归一化重测仅 19.1%。引用该项目时不可使用该数字。

同理，MM-Fi 研究曾把虚高的 91.86% 主动修正为 82.69%/83.59%。

尚未攻克 · 自有 ESP32 数据

在自有 ESP32 数据（2,046 配对窗口）上，所有微调跑法均未超过 mean-pose 基线（95.9% PCK@20）：预训练微调只得 65.0%，从零训练 0%。即仓库内实时姿态模型（pose_v1，PCK@20=3.0%，运行时为 confidence=0 桩）仍是低于目标的 first-cut。

ADR-079 诚实面对 "CSI-only 姿态 PCK@20≈2.5%" 的现实，采用"训练时用 MediaPipe 相机做教师、部署时无相机"的配对训练路线，目标 PCK@20 ≥35%（数据收集/评估阶段仍未完成）。

可背书 · Measured

只有以下数字是"已测量可背书"的：MM-Fi in-domain torso-PCK@20 82.69%（单模型）/ 83.59%（集成）（注意：同分布随机划分）；对比编码器 82.3% temporal-triplet；WiFlow-STD 重训复现 96.61%（他人数据集）。

09总结与展望

RuView 是一个工程完成度极高的 WiFi 空间感知平台：从 ESP32 固件（v0.8.4）到 Rust 信号处理引擎（42 crates）、四层模型栈、65 个 WASM 边缘模块、PyPI 轮子与 HuggingFace 发布链路，构成了一条"芯片 → 服务器 → 浏览器/智能家居"的完整闭环；205 个 ADR 与严格的证据等级制度（MEASURED / CLAIMED / DATA-GATED）体现了罕见的工程诚实。

已经成立的

  • 端到端链路打通：ESP32 → UDP → Rust 服务器 → WS/MQTT（ADR-059）；
  • MM-Fi 基准上 83.59% torso-PCK@20，超过 MultiFormer / CSI2Pose；
  • 效率前沿出色：36.7 KB int4 模型 0.135 ms 单线程推理；
  • WiFlow-STD 复现 96.61%，并证伪其发布 checkpoint；
  • 边缘工程（WASM 热加载、QEMU 测试、Ed25519 签名 OTA）成熟。

仍待突破的

  • 自有 ESP32 真实数据上姿态估计尚未超越 mean-pose 基线——"data-bound, not infra-bound"；
  • 跨受试者（64%）与跨环境（~10%）泛化是核心瓶颈，LoRA 房间适配是当前解法；
  • ESP32 真机延迟、临床类健康指标仍是 DATA-GATED；
  • ADR-079 配对训练路线（相机教师 → 无相机部署）的数据收集与评估尚未完成；
  • 20 Hz 实时预算下的关键性能问题待优化（预计可省 30–80% 帧预算）。

展望：若配对数据采集规模补齐、LoRA 房间适配产品化，RuView 有机会把"83% 的基准成绩"转化为"真实房间里的可用感知"；其自监督 AETHER 编码器（无标签、8 KB 量化）为"无摄像头自学习"提供了可持续演进的技术底座。
